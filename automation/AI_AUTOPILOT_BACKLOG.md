# SW AI OFFICE 자동 개발 백로그

기준: 2026-11-23
목표: 2026-11-30까지 핵심 업무 흐름이 실제로 동작하는 최소 버전을 안정적으로 가동한다.
범위: 기존 6개 개발 분야와 이미 합의된 기능만 유지한다. 신규 기능 확장은 하지 않는다.

## 우선순위 1 — 실제 실행 진입점 일치
- 현재 `index.html`은 `sw-ai-office-v7(claude).html`로 이동한다.
- 개발 진행현황 및 v3.15 연동 설치 문서는 `office-v315-integrated.html`을 업무처리 연동 실행 진입점으로 설명한다.
- 저장소의 실제 파일·테스트·배포 설정을 대조해 GitHub Pages 기본 진입점이 최신 업무연동 화면을 여는지 확인한다.
- 진입점 수정이 안전하다는 근거가 확인되면 수정하고, 회귀 테스트를 추가한다.
- 단, 3D 사무실 통합 PR이 미병합인 상태에서 해당 PR을 무시하고 임의의 디자인 파일로 교체하지 않는다.

## 우선순위 2 — 대표 지시에서 Worker 전달
- 대표가 본부장 알렉스를 선택해 보낸 지시만 업무처리 Worker로 전달한다.
- 다른 직원과의 개인 대화는 기존 대화 흐름을 유지한다.
- 직원 명단, 대표이사 식별, 팀·직책 매핑이 정확한지 검증한다.
- 대표이사는 단테, 법무팀장은 피터다. 과거 문서의 반대 표기는 오래된 정보로 취급한다.

## 우선순위 3 — 수행·협업·재개
- taskId/idempotencyKey를 사용해 중복 접수를 막는다.
- 중단·시간초과·일시적 오류 때 기존 업무를 안전하게 재개한다.
- 실제 진행 상태와 오류 원인을 사용자에게 표시하고, 완료되지 않은 업무를 완료로 표시하지 않는다.

## 우선순위 4 — 검수·보고·대표 승인
- 전문 직원 결과와 팀장 검수 결과가 최종 보고에 반영되는지 확인한다.
- 대표 승인/반려는 대표 전용 인증을 사용하고 서버 이력에 남긴다.
- 결과물과 감사 이력을 새로고침 후에도 복원할 수 있는지 검증한다.

## 우선순위 5 — 화면과 운영성
- 데스크톱 및 iPad 화면에서 주요 업무 지시·대화·이력 기능이 사용 가능한지 검증한다.
- 기존 사무실 디자인, 가구 배치, 직원 캐릭터를 근거 없이 변경하지 않는다.

## 변경 금지 및 외부 확인 필요
- 운영 Worker 배포, Secret 변경, 운영 D1 스키마/데이터 변경, 백업 복원, GitHub Pages 공개 설정 변경은 이 자동 에이전트가 수행하지 않는다.
- 운영 Worker/D1의 실제 상태와 end-to-end 실사용 검증은 운영 계정 접근이 확인된 후 별도 절차로 검증한다.
- 승인 원본 HTML은 덮어쓰지 않는다.
